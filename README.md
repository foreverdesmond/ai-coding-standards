## 用了能得到什么

- **普通人**：零基础也能指挥一支 AI 团队，把脑子里的产品从 0 造到 1，而且质量心里有底。
- **项目负责人**：风险看得见、外部操作不失控、成品质量可控可验收。
- **不绑架技术**：不绑定任何编程语言、框架或 AI 模型；小改动走轻量路线，不会为了一个小事被流程压死。

## 为什么需要它

AI 写代码已经很猛了。但对一个不懂软件工程、只是想"造个产品出来"的普通人来说，最怕的无非三件事：

- **范围乱跑**：本来想做个小功能，AI 越做越大、越做越偏。
- **边界被踩**：你没说"别碰数据库"，它就真去建表、删表、清空数据。
- **"看起来写完了，其实没对"**：代码能跑、测试全绿，可一上真实环境就出岔子。

你真正想要的，从来不是"代码长什么样"，而是**"成品靠谱不靠谱"**。但 AI 不会自己对你保证这一点——它只会努力把眼前的任务做完。

这套规范，解决的就是一句话：

> **用 AI 开发，怎么让整个过程可控。**

## 它的核心思路

### 1. 根子是成熟的软件工程流程，不是拍脑袋

专业软件团队本来就有分工：有人定需求、有人做设计、有人写代码、有人独立审查、有人负责集成、有人做验证。这套规范只是把这套成熟流程，拆成了 6 个清晰的角色（需求/设计 → 实现 → 独立审查 → 集成 → 验证 → 总调度），让 AI 能一个萝卜一个坑地嵌进去，且每个角色都**不能替对方拍板**。

### 2. 人守门，Agent 干活

你只管三件事：

- **说清需求**：要做什么、不做什么；
- **划清边界**：哪些东西 AI 绝对不能碰；
- **在门禁处拍板**：这一步质量可不可控、能不能往下走。

至于探索代码、写实现、跑测试、合并提交——全部交给对应角色的 Agent。你不必懂代码，只要看得懂"这一步的证据齐不齐、结论稳不稳"。

### 3. 三道保险，专治"看起来完了其实没对"

- **分层验证（L0–L3）**：单测通过只是最底层（L0），后面还有集成、真实环境验证。一句话——*单测绿了不等于生产对了*。
- **职责分离**：写代码的人不能审自己，更不能自己合并自己；审查、集成、合并由不同角色各管一段。
- **持久台账**：每一步的状态都记下来、可审计、可恢复。中途断了也能接着跑，不会"状态一丢全乱"。

### 4. 为什么是 Hermes 来当总调度

这套规范在演进过程中，调度主控从零迭代到今天，最终选定由 **Hermes** 担任总调度（Coordinator），而不是自己用脚本或命令行去拼一套调度——因为在这一块，Hermes 的能力明显更出色：任务台账、定期巡检对账、任务指派，都比命令行实现做得更好、也更省（token）。

更关键的一点是：Hermes 出色的**记忆与学习进化能力**，让这套规范不再是一份写死之后就不会变的"死文档"，而是能随项目实践**持续进化**的活标准。你用得越多，它越懂你的项目。

## 它不是什么

- 不是让 AI 自己瞎跑、自治拍板的"全自动工厂"。
- 不是替你做业务决策——*做什么、值不值得做，永远是你拍板*。
- 不要求你懂代码，也不要求你懂软件工程术语。
- 不绑架你的技术栈：你用什么语言、什么框架、什么模型，它都接得住。

## 怎么开始

四步就能跑起来，普通人也能照着做：

1. **写清楚"要做什么、边界在哪"**：先用 01、02 把背景和需求说清，划出 AI 不能碰的红线。
2. **让总调度（Hermes）接管派发**：它读规范、建台账、把任务指给对应 Agent，你不用管中间怎么排。
3. **Agent 各司其职**：探索、编码、测试、审查、集成，按角色分工自动流转。
4. **你在门禁处看证据、拍板**：每一关给你看"证据齐不齐、结论稳不稳"，你点头才往下走。

小改动走轻量路线，流程很轻；跨模块、高风险的任务才走完整链路——*重活才用重流程*。

## 版本与演进

本规范从真实多 Agent 开发实践中踩坑、复盘、迭代而来，目前为 **V2.5 定稿基线**。它本身就是"边用边进化"的产物：新发现的稳定流程缺陷会反向修订本规范，新规则必须说明解决的通用风险，而不是只针对单次事故写死。历史已审核决定与 V2.5 新决定见各文档的修订记录。
