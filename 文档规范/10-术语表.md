## 1. 目的

本文汇总本仓库规范中使用的固定术语、缩写与英文术语的官方中文译法，作为跨文档一致表达的基线。翻译、评审或新增文档时，术语译法以本文为准，避免同一概念在文档间漂移。

## 2. 角色与调度

| 中文 | 英文 / 原文 | 处理说明 |
|---|---|---|
| 总调度（Hermes） | Coordinator (Hermes) | Hermes 是该角色的实现实例 / codename，不是 Coordinator 的同义翻译；正文中出现时记作"总调度（由 Hermes 实现）"或"Coordinator—implemented by Hermes"。 |
| 开发 | Implementer | 首次实现 + 返工 + L0 单测的执行角色。 |
| 审核 | Reviewer | 独立代码 / 设计 / 文档审查角色。 |
| 集成 | Integrator | 将已审核提交合并到迭代或主分支的执行角色。 |
| 测试验证 | Validator | 合并后全量测试与回归验证角色。 |
| 文档 / 设计审核 | Doc/Design Reviewer | 文档、设计、工作包与上下文包的审查角色。 |
| 执行载体 | Execution Carrier | WorkBuddy / Codex / Human 等实际执行方，区别于角色（Role）。 |
| 执行机制 | Execution Mechanism | 即 ExpectedExecutionKind：由「载体策略制品」当前版本决定，非静态枚举（V3.0）。 |
| 伪独立自审 | Pseudo-Independent Self-Review | 禁止用不同载体名伪装独立审查；角色独立性须由不同 InvocationID 与执行实例证明。 |

## 3. 上下文、基线与包

| 中文 | 英文 / 原文 | 处理说明 |
|---|---|---|
| 上下文包（Context L2） | Context Package (Context L2) | 按风险生成的单任务导航包；L1 为稳定架构资料，L3 为执行者自主调查。 |
| 上下文 L1 | Context L1 | 项目级稳定操作说明，物理载体为仓库根 `AGENTS.md`。 |
| 不可变基线 | Immutable Baseline | 需求 / 设计 / 任务 / 文档 / 上下文的不可歧义引用（Git commit/tree、受控 revision、diff hash 或批准快照）。 |
| 代码基线 | CodeBaseSHA | 任务起点 commit 的 SHA。 |
| 头提交 | HeadSHA | 任务分支当前提交 SHA；新 HeadSHA 自动使旧 Review 失效（Superseded）。 |
| 审核范围 | ReviewedCommitRange / ReviewedCommitSet | 实际审核的 commit 区间与集合。 |

## 4. 状态、台账与门禁

| 中文 | 英文 / 原文 | 处理说明 |
|---|---|---|
| 台账 | Ledger / Tracking Ledger (Ledger) | 任务运行状态唯一实时真源（本地 JSON + 可选 SQLite，不进 Git）；偏财务语义的"台账"统一改译为状态追踪 Ledger，不再用账本式表述。 |
| 任务状态 | TaskState | Planned → … → Integrated → IntegrationVerified 等开发流程状态。 |
| 证据状态 | EvidenceState | Unread / Received / PendingVerification / Validated / Rejected / Superseded / Consumed。 |
| 执行载体状态 | Carrier Status | NotCreated / Provisioning / Running / Idle / NeedsAttention / Completed / Unavailable / Cancelled。 |
| 待消费 | PendingConsumption | 已产生、待 Hermes 读取并幂等消费的信号状态。 |
| 已接受任务 | TaskAccepted | 独立 Review 通过后形成，具备进入迭代集成资格。 |
| 已集成 | Integrated | 精确已审核提交合并入目标分支后的状态。 |
| 集成已验证 | IntegrationVerified | Integrator 合并后运行受影响集成检查通过后的状态。 |
| 候选冻结 | Candidate Freeze | 项目负责人冻结迭代候选的 human-gated 事件，触发 Level 1 派发。 |
| 合并已批准 | MergeApproved | 最终合并审核通过，且项目负责人明确授权后的状态。 |
| 已合并 | Merged | 主分支合并执行完成后的状态（不自动等于 ReleaseReady）。 |
| 冻结 | Frozen / Freeze | 指候选版本被锁定不再变更；与"候选冻结"同义，须明确为受控锁定而非临时挂起。 |


### 4.1 载体策略与并发（V3.0 新增）

| 中文 | 英文 / 原文 | 处理说明 |
|---|---|---|
| 载体策略制品 | Carrier Policy Artifact | 定义可用执行载体与分配规则的版本化数据文件；载体选择唯一真源。规范只引用其契约，不复制内容 |
| 策略不可变摘要 | PolicyArtifactDigest | 载体策略制品的密码学摘要（如 sha256）；每次派发随 PolicyVersion 记录于运行台账，防同版本篡改 |
| 协调者纪元 | CoordinatorEpoch | 调度权的 FencingToken：单调递增，任一时刻仅一个当前所有者；非当前 Epoch 的派发/消费一律拒绝 |
| 原子条件换主 | Atomic Conditional Takeover | 接管调度权仅当「当前 Epoch 与 StateRevision 仍匹配」时生效；否则接管失败 |
| 移交标识 | TransferID | 一次调度权移交的唯一标识；正常移交需新旧双方确认回执 |
| 失联恢复超时 | LostOwnerTimeout | 旧调度者失联判定阈值（默认 2 个调度周期）；超时后经 Richy 授权进入恢复模式接管 |

## 5. 验证层级与证据

| 中文 | 英文 / 原文 | 处理说明 |
|---|---|---|
| 验证层级 0–3 | Verification Level 0–3 | L0 单任务、L1 迭代集成、L2 生产形态系统、L3 真实外部环境。 |
| 未运行 | NotRun | 因环境 / 授权缺失未执行的验收项；须登记原因、风险与例外批准，不得伪装为通过。 |
| 替身 | Stub / Mock / Fake | 测试替身；须声明能证明与不能证明的边界。 |
| 证明缺口 | Proof Gap | 测试替身或环境限制导致无法证明真实行为的缺口。 |

## 7. 调度协议与恢复

| 中文 | 英文 / 原文 | 处理说明 |
|---|---|---|
| 幂等派发键 | DispatchKey | IterationID + TaskID + Stage + TargetIdentity 去重；调度权唯一性由 CoordinatorEpoch FencingToken 保证（V3.0）。 |
| 调用标识 | InvocationID | 每次派发的唯一标识；同一任务同一阶段仅允许一个有效实例。 |
| 执行引用 | ExecutionRef | 统一执行载体身份（替代旧 clientThreadId → threadId 两段式）。 |
| 对账 | Reconciliation | Hermes 消费台账信号并做状态核对；与"巡检"统一为"对账"，不再混用。 |
| 周期巡检 | Periodic Reconciliation | cron 兜底对账（约 1 分钟），作为事件通道兜底。 |
| 三级恢复 | Three-Tier Recovery | 热恢复 / 冷恢复 / 灾难恢复。 |
| 最大安全状态 | Maximum-Safe State | 恢复时只恢复到证据支持的最高状态。 |
| 调度协议验收 | Scheduling-Protocol Canary | 无业务副作用场景验收控制平面。 |
| 验收失败 | CanaryFailed | Canary 未通过的状态；冻结真实高风险迭代启动直至通过或明确豁免。 |

### 8.1 执行故障与豁免（V3.0 新增）

| 中文 | 英文 / 原文 | 处理说明 |
|---|---|---|
| 执行故障 | ExecutionFailure | `completed` 但缺结构化协议头、或零业务结论——不得推进业务状态；补发 ≤1 次，超限 PendingVerification |
| 最大自动尝试次数 | MaxAutomaticAttempts | 按 TaskID+Stage+TargetIdentity 持久化计数；默认 3 上限 3，换主/换实例不重置；达上限转 NeedsAttention |
| 代码不可变约束 | Code Immutability Constraint | Reviewer/Validator 可用 danger-full-access 构建+测试，但不得改受跟踪业务源码/commit 候选/merge；前后 HEAD-tree 对账，变化即结论无效 |
| 干净检出验证 | Clean-Checkout Verification | L2+ 必须在精确候选 commit 的独立 detached worktree 验证；gitignore 依赖须有可复现受控回退来源 |
| 豁免边界七项组 | Waiver Boundary Tuple | 命令/场景 + 失败签名 + 影响范围 + 风险 + 替代证据 + 授权人 + 到期候选身份；七项缺一无效 |
| 豁免通过 | VerifiedWithWaivers | 带有效豁免的通过级结论；不满足要求「无豁免」的门禁。`Verified` 表示无豁免完全通过 |
