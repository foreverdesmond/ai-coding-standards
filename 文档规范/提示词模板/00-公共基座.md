审核或执行目标：真实编码任务使用 `<code-base-sha>..<head-sha>`；纯文档、调查或已批准例外才使用 `<PR revision / diff hash / stable worktree snapshot>`。

共同约束：

1. 保护用户和其他任务已有改动，不得覆盖无关变化。
2. 未经授权不得连接、修改或删除真实外部资源；破坏性操作停止并请求精确授权。
3. 所有测试和结论绑定审核目标、环境、命令或步骤与时间；未运行项标记 `NotRun`。
4. 只使用角色模板允许的状态；发生冲突时使用该角色的阻塞或失败状态，并附证据。
5. 最终输出列出证据、限制和剩余风险，不能只说“已完成”。
6. 严格遵守角色的 Git 权限；worktree 只是工作目录，不能替代分支和 commit 身份。
7. 最终输出必须先给出角色模板规定的结构化协议头，并原样返回 `ProtocolVersion`、`IterationID`、`TaskID` 和 `InvocationID`；不得省略或自行改写身份。
8. 若实际执行机制、模型、分支、基线或文档 Ref 与上述值不一致，停止并报告；不得在错误目标上继续。
9. 本任务只能履行 `<role>`。项目明确要求 Codex 独立子任务时，不得自行改用子 Agent、其他线程或当前任务吞并职责。
10. 开始、求助、完成或形成 Review/集成结论时，必须调用 `StateUpdateToolPath`；工具在共享锁内重新读取最新 `StateRevision`，只更新 `StateRecordID`，递增 `SignalRevision` 并把 `SignalState` 写为 `PendingConsumption`。工具报告成功后才能输出 final。
11. 状态记录至少写入 `InvocationID`、`ExecutionThreadID`、`ExecutionStatus`、`TaskState`、`HeadSHA/ReviewTarget`、`Verdict/BlockerType`、`ProducedAt`、`NextAction` 和简短摘要。长日志、完整 diff 与完整 final 不写入状态区。
12. 状态写入失败时不得声称状态已发布；final 必须明确 `StatePublishFailed`。不得依赖跨任务 API 事件替代共享本地状态发布。
