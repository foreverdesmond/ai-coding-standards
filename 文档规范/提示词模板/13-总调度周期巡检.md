# 总调度周期对账（Hermes cronjob 配置）

> 规范版本：V2.5
> 文档状态：已审核通过（V2.5 定稿基线）
> 作者：WorkBuddy（受 Hermes 总调度委派）
> 创建日期：2026-08-20
> 最后更新：2026-08-20
> 审核人：Richy（已审核）

目标：Hermes 以 cron 定时任务对所属迭代 `<iteration-id>` 执行一次可重复、幂等的台账消费与健康对账，作为事件通道的兜底。不得常态遍历任务列表或依赖跨任务 API 事件发现完成结果。

## 1. cron 配置

```text
ProtocolVersion: <protocol-version>
IterationID: <iteration-id>
HermesInstanceRef: <hermes-instance-id>
LedgerLocation: <台账位置>
CanonicalTaskDocumentPath: <Git 管理的任务定义/快照路径>
TaskDocumentBaselineRef: <immutable-ref>
CronInterval: <约 1 分钟；5 段 cron 或等价表达>
StopConditions: <stop-conditions>
NotifyConditions: <notify-conditions>
```

cron 精度为分钟级（依据《Hermes能力边界清单》§4）。事件（飞书 / Codex 网关轮询）优先消费，cron 兜底对账补事件丢漏。

## 2. 每轮顺序

1. 读台账，验证 Schema、IterationID、StateRevision、RecordID 唯一性。
2. 台账缺失、损坏、版本回退时进入 `RecoveryOnly`，按 `09-Hermes调度与运行时台账规范` §13 恢复，禁止派发并报告恢复需要。
3. 若 `Paused=true`，不消费后推进业务状态、不创建任务、不返工、不 Review、不集成；输出暂停状态后结束本轮。
4. 收集全部 `SignalState=PendingConsumption` 的记录。
5. 没有待消费记录时不调用任务列表、不逐载体读取；只检查台账完整性、文档快照、当前门禁所需 Git 祖先关系。
6. 有待消费记录时按 `RecordID + SignalRevision` 去重，只读取该记录绑定的 `ExecutionRef`，不读取其他执行载体。
7. 校验 Invocation、Task、角色、分支、SHA、ReviewTarget/Verdict 或集成结果；用 Git 和不可变文档交叉验证。
8. 已验证结果触发一次状态转换和至多一个新 DispatchKey；随后写入 `ConsumedAt/ConsumedBy`、汇总状态和下一阶段记录并递增 `StateRevision`。
9. 定向读取失败时保留 `PendingConsumption`，记录 `ControlPlaneError` 并通知；不得改扫其他载体或写成代码 `Blocked`。

## 3. 禁止

- 用 UI idle/completed 推断"没有结果"；
- 把跨任务 API 事件或任务列表摘要作为状态发现入口；
- 无 `PendingConsumption` 时扫描全部执行载体；
- 用 Git HEAD 未变化推断"Review 没有结论"；
- 把派发请求标识当成失败；
- 重复派发已有有效 DispatchKey 的任务；
- 把 ToolRuntime/读取错误写成代码 `Blocked`；
- 在 `Paused` 或 `RecoveryOnly` 中推进业务状态。

## 4. 本轮输出

```text
ProtocolVersion:
EventType: ReconciliationCycleResult
IterationID:
HermesInstanceRef:
CoordinatorMode: Active / Paused / RecoveryOnly
CheckedAt:
TaskDocumentPath:
LedgerLocation:
StateRevisionBefore:
StateRevisionAfter:
ConsumedRevisionBefore:
ConsumedRevisionAfter:
PendingRecords:
TargetedExecutionsRead:
SignalsValidated:
SignalsConsumed:
GitHeadsChecked:
RealStateChanges:
NewDispatches:
ControlPlaneErrors:
BusinessBlockers:
NotificationDecision: Notify / Quiet
NextInspection:
```

只有在实际填写文档版本、待消费记录、定向执行载体和必要 Git 检查后，才允许写 `RealStateChanges: None`。通知规则优先报告新结论、需用户授权、台账损坏、定向读取失败或真实阻塞；纯粹无变化默认静默（通知 0 token，读台账结构化字段 + 模板拼装）。
