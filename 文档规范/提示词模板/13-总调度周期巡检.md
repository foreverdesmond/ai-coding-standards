# 总调度周期巡检

目标：在 `<coordinator-thread-id>` 所属迭代 `<iteration-id>` 中，以 `<shared-runtime-state-path>` 共享 JSON 为唯一实时任务状态入口，执行一次可重复、幂等的状态消费与健康巡检。不得常态遍历任务列表或依赖跨任务 API 事件发现完成结果。

固定配置：

```text
ProtocolVersion: <protocol-version>
IterationID: <iteration-id>
CoordinatorThreadID: <coordinator-thread-id>
RuntimeLedgerLocation: <ledger-location>
TaskDocumentBaselineRef: <immutable-ref>
CanonicalTaskDocumentPath: <shared-absolute-path>
SharedRuntimeStatePath: <shared-local-json-path>
TaskStateWriteLockPath: <lock-path>
StateUpdateToolPath: <atomic-update-tool-path>
WatchdogInterval: <interval>
MaxConsecutiveNoChangeCycles: <count>
StopConditions: <stop-conditions>
NotifyConditions: <notify-conditions>
```

每轮必须按顺序执行：

1. 调用 `StateUpdateToolPath heartbeat`，在锁内读取 `SharedRuntimeStatePath`，验证 Schema、IterationID、StateRevision、RecordID 唯一性并更新看门狗计数；不得自行读写拼接 JSON。
2. 共享状态缺失、损坏、版本回退或路径不是固定绝对路径时进入 `RecoveryOnly`，以开发任务文档快照和 Git 恢复，禁止派发并报告恢复需要。
3. 若 `Paused=true`，不得消费后推进业务状态、创建任务、发送返工、创建 Review 或执行集成；输出暂停状态后结束本轮。
4. 获取协调租约。未获得租约时只报告已有 Owner，不产生副作用。
5. 比较 `StateRevision` 与 `CoordinatorConsumedRevision`，收集全部 `signalState=PendingConsumption` 的记录。
6. 没有待消费记录时不得调用任务列表、不得逐线程读取；只检查共享状态完整性、文档快照、当前门禁所需 Git 祖先关系和租约健康。
7. 有待消费记录时按 `RecordID + SignalRevision` 去重，只读取该记录绑定的 `ExecutionThreadID`，不读取其他线程。
8. 校验 Invocation、Task、角色、分支、SHA、ReviewTarget/Verdict 或集成结果；用 Git 和不可变文档交叉验证。
9. 已验证结果触发一次状态转换和至多一个新 DispatchKey；随后写入 `ConsumedAt/ConsumedBy`、汇总状态和下一阶段记录并递增 `StateRevision`。
10. 定向读取失败时保留 `PendingConsumption`，记录 `ControlPlaneError` 并通知；不得改扫其他线程或写成代码 `Blocked`。
11. 所有写入只能调用统一工具；工具取得短时锁、重新读取最新版本、拒绝覆盖更高 `StateRevision`，经 `fsync` 和原子替换后释放锁。
12. 若存在待消费记录或本轮发生业务 `StateRevision` 变化，看门狗无变化计数归零；否则递增一次。达到 `MaxConsecutiveNoChangeCycles` 时，暂停自身自动巡检并记录 `stopRequested=true`；未达到时保持原巡检计划。

禁止：

- 用 UI idle/completed 推断“没有结果”；
- 把跨任务 API 事件或任务列表摘要作为状态发现入口；
- 无 `PendingConsumption` 时扫描全部线程；
- 写入当前 worktree 的任务文档副本；
- 用 Git HEAD 未变化推断“Review 没有结论”；
- 把创建请求标识当成失败；
- 在明确要求 Codex 子任务时使用 `spawn_agent` 或当前任务自行完成；
- 重复派发已有有效 DispatchKey 的任务；
- 把 ToolRuntime/读取错误写成代码 `Blocked`；
- 在 `Paused` 或 `RecoveryOnly` 中推进业务状态。
