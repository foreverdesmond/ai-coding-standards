# 总调度冷恢复（Hermes 重启恢复规则）

> 规范版本：V2.5
> 文档状态：待审核
> 作者：WorkBuddy（受 Hermes 总调度委派）
> 创建日期：2026-08-20
> 最后更新：2026-08-20
> 审核人：Richy（待审）

目标：在台账缺失、损坏、版本回退或无法证明恢复点时，从最后有效文档快照和 Git 重建 `<iteration-id>` 的最大安全状态。只有文档记录指出待消费或缺失证据时，才定向读取对应执行载体。恢复期间不得推进业务状态或派发后续任务。

## 1. 恢复分级（依据《Hermes能力边界清单》§7）

| 级别 | 触发 | Hermes 动作 | 失败处理 |
|---|---|---|---|
| 热恢复 | 单次工具/调用偶发异常 | 记日志，从最近台账快照自动续跑；重试 | 仍不行，等 cron 对账兜底 |
| 冷恢复 | 进程崩溃/重启 | 全自动读台账 + Git 重建 `ConsumedRevision` → `RecoveryOnly` 校验 → 恢复 | **失败自动升级灾难级** |
| 灾难恢复 | 台账丢失/损坏（或冷恢复失败） | 从 Git 任务文档快照重建，确定可证明状态，其余降级待核实 | **需项目负责人（Richy）介入批准** |

## 2. 冷恢复输入

```text
ProtocolVersion: <protocol-version>
IterationID: <iteration-id>
RecoveryInvocationID: <invocation-id>
HermesInstanceRef: <hermes-instance-id>
LedgerLocation: <台账位置>
CanonicalTaskDocumentPath: <Git 管理的任务定义/快照路径>
TaskDocumentBaselineRef: <immutable-ref>
Repository: <repository>
IterationBranch: <iteration-branch>
TaskBranchPattern: <pattern>
KnownTaskIDs: <list>
```

## 3. 强制模式

```text
CoordinatorMode: RecoveryOnly
DispatchAllowed: false
IntegrationAllowed: false
BusinessWritesAllowed: false
```

## 4. 执行步骤

1. 读取不可变任务定义；优先验证台账，其缺失或损坏时从 `CanonicalTaskDocumentPath` 最后一个结构有效的 `TASK-STATE-EXCHANGE` 快照恢复任务图、角色、依赖、基线、稳定状态和未消费记录。
2. 扫描任务分支、迭代分支、worktree、提交、祖先关系和分支包含关系。
3. 只对状态记录为 `PendingConsumption`、`PendingVerification` 或证据缺失的阶段，按其中的 `ExecutionRef` 定向查找执行载体。
4. 只读取上述目标任务历史；禁止恢复为全量任务列表/载体扫描。
5. 为每条证据计算 Fingerprint，记录来源、原始时间、恢复时间和置信度。
6. 按职责核验：文档证明计划，Git 证明代码，Reviewer final 证明 Verdict，执行载体历史证明执行，明确消息证明授权。
7. 对每个任务计算最大安全状态；不得从代码结果反推 Review 或授权。
8. 标记重复实例、错误执行机制、失效 Review、未知合入、缺失证据和冲突。
9. 写回台账并保存旧状态备份；稳定后更新开发任务文档快照，派生证据目录只保存长证据。
10. 输出恢复报告，保持 `RecoveryOnly`，等待项目负责人或批准审计者给出 `RecoveryApproved`。

## 5. 最大安全状态规则

- 仅有 commit：`EvidenceIncomplete`；
- 开发 final + Git 匹配：最多 `Submitted`；
- 有效 `ChangesRequested`：恢复该状态并查找新 Head；
- `Approved` 与当前 Head 精确匹配：恢复 `TaskState=TaskAccepted`，但在恢复审核通过前不得据此派发；
- 当前 Head 改变：旧 Review `Superseded`；
- 代码已合入但无门禁证据：`IntegrationUnverified`；
- Review 历史丢失：建议重新 Review，不建议重新开发；
- 授权丢失：重新取得授权。

## 6. 输出

```text
ProtocolVersion:
EventType: RecoveryReport
IterationID:
RecoveryInvocationID:
HermesInstanceRef:
CoordinatorMode: RecoveryOnly
TaskDocumentBaselineRef:
GitRefsScanned:
ExecutionsDiscovered:
ExecutionHistoriesRead:
RecoveredEvents:
RecoveredTaskStates:
SupersededEvidence:
DuplicateOrInvalidInvocations:
IntegrationUnverified:
MissingEvidence:
Conflicts:
RecoveryConfidenceByTask:
LedgerWrittenAt:
RecoveredStateRevision:
TargetedExecutionsRead:
RequiredReReviews:
RequiredOwnerDecisions:
Verdict: ReadyForRecoveryApproval / RecoveryIncomplete
```

即使 `Verdict: ReadyForRecoveryApproval`，也不得自行切换为 Active 或派发任务。
