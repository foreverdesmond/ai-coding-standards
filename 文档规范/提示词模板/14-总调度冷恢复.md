# 总调度冷恢复

目标：在开发任务文档状态交换区缺失、损坏、版本回退或无法证明恢复点时，从最后有效文档状态和 Git 重建 `<iteration-id>` 的最大安全状态。只有文档记录指出待消费或缺失证据时，才定向读取对应子任务。恢复期间不得推进业务状态或派发后续任务。

输入：

```text
ProtocolVersion: <protocol-version>
IterationID: <iteration-id>
RecoveryInvocationID: <invocation-id>
CoordinatorThreadID: <coordinator-thread-id>
RuntimeLedgerLocation: <ledger-location>
TaskDocumentBaselineRef: <immutable-ref>
CanonicalTaskDocumentPath: <shared-absolute-path>
SharedRuntimeStatePath: <shared-local-json-path>
TaskStateWriteLockPath: <lock-path>
StateUpdateToolPath: <atomic-update-tool-path>
Repository: <repository>
IterationBranch: <iteration-branch>
TaskBranchPattern: <pattern>
KnownTaskIDs: <list>
KnownThreadHints: <titles, ids, parent task>
```

强制模式：

```text
CoordinatorMode: RecoveryOnly
DispatchAllowed: false
IntegrationAllowed: false
BusinessWritesAllowed: false
```

执行步骤：

1. 读取不可变任务定义；优先验证 `SharedRuntimeStatePath`，其缺失或损坏时从 `CanonicalTaskDocumentPath` 最后一个结构有效的快照恢复任务图、角色、依赖、基线、稳定状态和未消费记录。
2. 扫描任务分支、迭代分支、worktree、提交、祖先关系和分支包含关系。
3. 只对状态记录为 `PendingConsumption`、`PendingVerification` 或证据缺失的阶段，按其中的 `ExecutionThreadID` 定向查找执行载体。
4. 只读取上述目标任务历史；禁止恢复为全量任务列表/线程扫描。
5. 为每条证据计算 Fingerprint，记录来源、原始时间、恢复时间和置信度。
6. 按职责核验：文档证明计划，Git 证明代码，Reviewer final 证明 Verdict，任务历史证明执行，明确消息证明授权。
7. 对每个任务计算最大安全状态；不得从代码结果反推 Review 或授权。
8. 标记重复实例、错误执行机制、失效 Review、未知合入、缺失证据和冲突。
9. 通过 `StateUpdateToolPath` 在短时锁保护下写回新的共享 JSON 并保存旧状态备份；稳定后更新开发任务文档快照，派生审计目录只保存长证据和租约。
10. 输出恢复报告，保持 `RecoveryOnly`，等待项目负责人或批准审计者给出 `RecoveryApproved`。

最大安全状态规则：

- 仅有 commit：`EvidenceIncomplete`；
- 开发 final + Git 匹配：最多 `Submitted`；
- 有效 `ChangesRequested`：恢复该状态并查找新 Head；
- `Approved` 与当前 Head 精确匹配：恢复 `TaskState=TaskAccepted`，但在恢复审核通过前不得据此派发；
- 当前 Head 改变：旧 Review `Superseded`；
- 代码已合入但无门禁证据：`IntegrationUnverified`；
- Review 历史丢失：建议重新 Review，不建议重新开发；
- 授权丢失：重新取得授权。

输出：

```text
ProtocolVersion:
EventType: RecoveryReport
IterationID:
RecoveryInvocationID:
CoordinatorThreadID:
CoordinatorMode: RecoveryOnly
TaskDocumentBaselineRef:
GitRefsScanned:
ThreadsDiscovered:
ThreadHistoriesFullyRead:
RecoveredEvents:
RecoveredTaskStates:
SupersededEvidence:
DuplicateOrInvalidInvocations:
IntegrationUnverified:
MissingEvidence:
Conflicts:
RecoveryConfidenceByTask:
LedgerWrittenAt:
RecoveredStateRevision:
TargetedThreadsRead:
RequiredReReviews:
RequiredOwnerDecisions:
Verdict: ReadyForRecoveryApproval / RecoveryIncomplete
```

即使 `Verdict: ReadyForRecoveryApproval`，也不得自行切换为 Active 或派发任务。
